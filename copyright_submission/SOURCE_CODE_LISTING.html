 28  ## 1. Description of the Work
 29  
 30  The College Assistant is a self-hosted software system that answers natural-language
 31  questions about a college's institutional records — courses, departments, faculty, fee
 32  structures, room allocations, class schedules, and examination timetables — through a
 33  web-based chat interface.
 34  
 35  The distinguishing characteristic of the work is its **multi-agent architecture**. Rather
 36  than passing a user's question to a single language model, the system decomposes the task
 37  across six cooperating software agents, each with a separate responsibility, prompt
 38  design, and failure mode. A question is classified by route, dispatched concurrently to a
 39  structured-data agent and a semantic-search agent, and the results are merged into a
 40  single natural-language answer.
 41  
 42  The system operates **entirely offline**. The language model runs locally via Ollama; no
 43  question, record, or fragment of institutional data is transmitted to any external
 44  service. This is a deliberate design constraint of the work, motivated by the privacy
 45  requirements of student and institutional data.
 46  
 47  A second distinguishing characteristic is the **layered database security model** built
 48  around machine-generated SQL. Because a language model composes queries that are then
 49  executed against a live database, the work implements four independent enforcement
 50  layers — a restricted PostgreSQL role, session-level read-only enforcement, an abstract
 51  syntax tree validator, and a table allowlist — such that the failure of any one layer
 52  does not permit unauthorized reads or any write whatsoever.
 53  
 54  ### Original elements claimed
 55  
 56  - The six-agent architecture and the orchestration logic that coordinates it
 57  - The prompt designs for query generation, routing, synthesis, and verification
 58  - The SQL safety validator and its four-layer enforcement model

 74  ## 2. Major Components
 75  
 76  ### Sync Worker — `sync_worker/`
 77  An independent long-running service that keeps the semantic search index consistent with
 78  the relational database. It polls nine institutional tables on a configurable interval,
 79  detects inserts and updates by comparing per-table high-water marks against a persisted
 80  state file, converts changed rows into natural-language text, generates vector embeddings
 81  locally, and upserts them into the Qdrant vector store. It maintains an append-only change
 82  queue as a durable record of processed work, and connects to the database strictly as the
 83  read-only role. Comprises the poller, change-queue writer, watermark state manager, row-to-
 84  text chunker, embedder, vector-store client, and a self-contained pipeline integration test.
 85  
 86  ### SQL Agent — `backend/sql_agent/`
 87  Translates a natural-language question into a validated, executable PostgreSQL `SELECT`
 88  statement. Introspects the live database schema at query time — so the prompt can never
 89  drift from the privileges actually granted — then submits the question and schema to the
 90  language model, and subjects the returned text to a validation stage before any execution
 91  occurs. The validator parses the output into an abstract syntax tree and rejects anything
 92  that is not a single `SELECT`, contains a write-class keyword token, references a table
 93  outside the allowlist, or fails to parse. It then rewrites the statement to impose a hard
 94  row cap. Every generated query is logged before execution, including rejected ones.
 95  
 96  ### RAG Agent — `backend/rag_agent/`
 97  Handles descriptive and open-ended questions that structured queries cannot answer. Embeds
 98  the incoming question using the same locally-hosted embedding model the sync worker uses,
 99  performs a similarity search against the vector store, and returns ranked passages with
100  provenance metadata identifying the source table and row for each result.
101  
102  ### Router Agent — `backend/router_agent/`
103  Classifies each incoming question to determine which retrieval strategy applies —
104  structured records, semantic search, or both — so that downstream agents are invoked only
105  when relevant. Designed to fail safe: an unparseable classification falls back to querying
106  both sources rather than guessing, and the fallback is recorded.
107  
108  ### Synthesis Agent — `backend/synthesis_agent/`
109  Merges structured query results and retrieved passages into a single coherent answer
110  grounded in the supplied evidence. Supports both a blocking mode and an incremental
111  streaming mode that emits the answer token by token, enabling the client to display text
112  as it is produced rather than after completion.
113  
114  ### Verification Agent — `backend/verification_agent/`
115  Checks a synthesised answer against its source evidence, identifies individual claims,
116  determines whether each is supported, and records the outcome to a persistent verification
117  log for later analysis. `[CONFIRM]` This agent is currently invoked from the experimental
118  evaluation harness and is not wired into the live request path.
119  
120  ### Orchestrator — `backend/orchestrator/`
121  Coordinates the agents into a single request pipeline. Resolves the route, dispatches the
122  structured and semantic retrieval steps concurrently, and merges the results. Implements
123  the graceful-degradation policy: when one retrieval source is unavailable the system
124  answers from the other and appends a plain-language notice explaining the limitation,
125  raising an error only when no usable source remains. Also implements input sanitisation
126  and the server-sent-events streaming protocol.
127  
128  ### Supporting subsystems
129  - **`backend/academics/`** — the institutional data model and its migrations; the
130    idempotent read-only-role provisioning command; the demonstration dataset loader.
131  - **`backend/accounts/`** — session-based authentication, staff-only authorisation, and
132    per-user rate limiting.
133  - **`backend/audit/`** — a persistent audit trail recording every question, the route
134    taken, the generated SQL, the final answer, latency, and prompt-injection indicators.
135  - **`backend/health/`** — separate liveness and aggregate-readiness endpoints, plus a
136    command that verifies the read-only lockdown by attempting a write and confirming
137    rejection.
138  - **`backend/experiments/`** — an evaluation harness measuring answer similarity against
139    a reference question-and-answer set, and a concurrent load-testing tool.
140  - **`frontend/`** — the React chat client, including streaming response handling.
141  - **Deployment** — Docker Compose orchestration of all services and an HTTPS reverse
142    proxy terminating TLS.

146  ## 3. Development Record
147  
148  *Ordering is established by filesystem timestamps; see the notice at the top of this
149  document regarding the reliability of the dates themselves.*
150  
151  ### Phase 1 — Foundation
152  Django project structure, service containerisation, React client scaffold, and the
153  institutional data model with its initial migration. Health-check endpoints and the
154  read-only role verification tool were established at this stage, before any agent was
155  built, so that the security model preceded the code it constrains.
156  
157  ### Phase 2 — Sync Worker
158  The incremental synchronisation pipeline: watermark-based change detection, the durable
159  change queue, row-to-text conversion, local embedding generation, vector-store upsert, and
160  an end-to-end pipeline test exercising the real components without mocking.
161  
162  ### Phase 3 — Agents
163  The six agents, implemented in dependency order — SQL agent (schema introspection, safety
164  validator, executor), RAG agent (embedding and retrieval), router agent (classification),
165  synthesis agent (answer generation), verification agent (claim checking and logging), and
166  finally the orchestrator coordinating them. Each agent was given a standalone demonstration
167  command allowing it to be exercised in isolation.
168  
169  ### Phase 4 — Evaluation
170  The experimental harness: similarity scoring against a reference answer set, model warm-up
171  handling, batch experiment runner with CSV and JSONL output, and a concurrent load tester
172  reporting time-to-first-token and total-response-time statistics.
173  
174  ### Phase 5 — Production Hardening
175  Automated first-run provisioning (migrations, read-only role creation, staff account,
176  demonstration data) via a self-configuring container entrypoint. Session-cookie
177  authentication replacing token storage, staff-only authorisation, rate limiting, the audit
178  log, input sanitisation, and secure-cookie and CSRF configuration. Shared client modules
179  were extracted and a uniform exception hierarchy introduced, enabling the
180  graceful-degradation policy. An HTTPS reverse proxy with internally-issued certificates
181  was added so that no service is exposed except over TLS.
182  
183  ### 26 July 2026 — Review and Registration Preparation
184  Production-readiness review. The read-only role provisioning script was rewritten to accept
185  its password as a parameter rather than containing a literal credential. Documentation
186  corrections and a non-technical operator runbook. Proprietary licence, per-file copyright
187  notices, this statement of work, and the source code submission bundle.

 5  # The site is named (localhost + whatever SERVER_HOST is set to) so Caddy's

 7  # trusted CA — no public domain or internet needed, suited to an internal LAN.
 8  # The browser talks only to Caddy (443); Caddy forwards /api/* to the Django
 9  # backend and everything else to the frontend, so the SPA and API share one
10  # HTTPS origin (no CORS, and session cookies get the Secure flag). Caddy also
11  # auto-redirects plain HTTP (80) to HTTPS.

14  	tls internal
15  	encode gzip
16  
17  	# API -> Django. SSE streaming is passed through unbuffered.

19  		reverse_proxy backend:8000 {
20  			flush_interval -1

22  	}

  4  -- Read-only Postgres role for the RAG agent.
  5  --
  6  -- WHAT THIS DOES:
  7  --   - Creates (or resets the flags on) a login role `rag_agent_ro` that:
  8  --       * cannot create databases, roles, or replicate
  9  --       * defaults every session to a read-only transaction (defense in depth,
 10  --         on top of the grants below — belt and suspenders)
 11  --       * has USAGE on the `public` schema but no privileges on any table
 12  --         until explicitly granted below
 13  --       * gets SELECT on the whitelisted tables ONLY — nothing else, no
 14  --         wildcard grants, no future-table auto-grants
 15  --
 16  -- YOU DO NOT NORMALLY NEED TO RUN THIS. The backend applies exactly these
 17  -- statements on every startup via `manage.py setup_readonly_role` (see
 18  -- backend/academics/management/commands/setup_readonly_role.py), reading the
 19  -- password from RAG_AGENT_RO_PASSWORD in .env. This file is the reference
 20  -- copy / manual fallback.
 21  --
 22  -- NO PASSWORD IS WRITTEN IN THIS FILE, deliberately — the secret lives only in
 23  -- .env (which is gitignored). The password is passed in as a psql variable.
 24  --
 25  -- HOW TO RUN MANUALLY (from the repo root, with the stack up):
 26  --   docker compose exec -T postgres psql -U postgres -d college_rag \
 27  --     -v pw="$RAG_AGENT_RO_PASSWORD" -f - < db/sql/create_rag_agent_ro.sql
 28  --
 29  -- Never replace :'pw' below with a literal password — that would put a live
 30  -- secret into a file that gets copied, committed, and shared.
 31  -- ============================================================================
 32  
 33  \if :{?pw}
 34  \else
 35      \echo 'ERROR: no password supplied. Re-run with -v pw="$RAG_AGENT_RO_PASSWORD"'
 36      \quit 1
 37  \endif
 38  
 39  -- Create only if missing. Done with psql's \if rather than a DO $$ block
 40  -- because psql does NOT interpolate :'pw' inside dollar-quoted strings — the
 41  -- variable would be sent to the server verbatim and fail.
 42  SELECT NOT EXISTS (
 43      SELECT FROM pg_catalog.pg_roles WHERE rolname = 'rag_agent_ro'
 44  ) AS role_missing \gset
 45  
 46  \if :role_missing
 47  CREATE ROLE rag_agent_ro LOGIN PASSWORD :'pw';
 48  \endif
 49  
 50  -- Keep the password in sync with .env even if the role already existed.
 51  ALTER ROLE rag_agent_ro LOGIN PASSWORD :'pw';
 52  
 53  ALTER ROLE rag_agent_ro
 54      NOSUPERUSER
 55      NOCREATEDB
 56      NOCREATEROLE
 57      NOREPLICATION
 58      CONNECTION LIMIT 10;
 59  
 60  -- Session-level default is a separate ALTER ROLE ... SET statement in Postgres
 61  -- (can't be combined with the role-attribute clauses above).
 62  ALTER ROLE rag_agent_ro SET default_transaction_read_only = on;
 63  
 64  -- Lock down the schema itself: PUBLIC (i.e. every role, by default) loses
 65  -- the implicit CREATE/USAGE it gets on a fresh database. rag_agent_ro then
 66  -- gets USAGE explicitly, and only USAGE — it can look up objects, not create them.
 67  REVOKE ALL ON SCHEMA public FROM PUBLIC;
 68  GRANT CONNECT ON DATABASE college_rag TO rag_agent_ro;
 69  GRANT USAGE ON SCHEMA public TO rag_agent_ro;
 70  
 71  -- Clean slate: strip any privileges this role may already have on every
 72  -- table in the schema, so re-running this script never leaves stale grants
 73  -- around if a table gets removed from the whitelist later.
 74  REVOKE ALL PRIVILEGES ON ALL TABLES IN SCHEMA public FROM rag_agent_ro;
 75  
 76  -- ----------------------------------------------------------------------------
 77  -- General institutional data ONLY — no per-student records. The agent's job
 78  -- is general Q&A (courses offered, departments, faculty, timetable, fee
 79  -- structure), not lookups tied to an individual student's identity.
 80  --
 81  -- Deliberately EXCLUDED (per-student / sensitive — see backend/academics/models.py):
 82  --   students, enrollments, attendance, exam_results, fee_payments
 83  -- Also excluded: Django's own auth_*/django_* tables (not college data at all).
 84  -- ----------------------------------------------------------------------------
 85  GRANT SELECT ON
 86      public.departments,
 87      public.faculty,
 88      public.programs,
 89      public.courses,
 90      public.courses_prerequisites,
 91      public.course_offerings,
 92      public.rooms,
 93      public.class_schedule,
 94      public.exam_timetable,
 95      public.fee_structure
 96  TO rag_agent_ro;
 97  
 98  -- No GRANT on sequences, functions, or other schemas — SELECT on the
 99  -- whitelisted tables is the entire privilege surface for this role.
100  
101  -- Sanity check: list what rag_agent_ro can now see (run separately or as
102  -- the last statement here; safe to leave in since it's read-only itself).
103  SELECT grantee, table_schema, table_name, privilege_type
104  FROM information_schema.role_table_grants
105  WHERE grantee = 'rag_agent_ro'
106  ORDER BY table_schema, table_name;

12  def _cosine(a, b):
13      dot = sum(x * y for x, y in zip(a, b))
14      na = math.sqrt(sum(x * x for x in a))
15      nb = math.sqrt(sum(y * y for y in b))
16      if na == 0 or nb == 0:
17          return 0.0
18      return dot / (na * nb)

22      return re.sub(r"\s+", " ", (text or "").lower().strip())
23

25  def string_similarity(a, b):
26      """Cheap lexical overlap via difflib — a secondary signal alongside the
27      semantic score, useful for spotting cases where the wording matches
28      closely vs cases where only the meaning does."""
29      return SequenceMatcher(None, _normalize(a), _normalize(b)).ratio()

32  def semantic_similarity(a, b):
33      """Cosine similarity of the two answers' embeddings (nomic-embed-text).
34      Returns None if embedding fails so the caller can fall back to the
35      string score rather than silently scoring 0."""
36      try:
37          va = embed_text(a or "")
38          vb = embed_text(b or "")
39      except Exception:
40          return None
41      return _cosine(va, vb)

45      """Returns a dict with both similarity scores and a correct/incorrect
46      verdict. Correctness is decided on the semantic score when available
47      (meaning matters more than exact wording for QA), falling back to the
48      string score if embeddings are unavailable."""
49      sem = semantic_similarity(final_answer, ground_truth)
50      stri = string_similarity(final_answer, ground_truth)

60          "correctness_basis": "semantic" if sem is not None else "string",

 3  import re
 4  
 5  # Defense-in-depth for the chat box. The real structural guarantees are
 6  # elsewhere — the SQL guard rejects anything touching non-allowlisted tables
 7  # or attempting writes, and the RAG agent is read-only — so a prompt-injection
 8  # attempt can't reach the database destructively. This layer caps abuse
 9  # (huge prompts burning LLM compute) and neutralizes control characters that
10  # could forge fake lines in the audit log or agent logs.
11  
12  MAX_QUESTION_LENGTH = 500
13  
14  # Strip C0/C1 control characters except normal whitespace (tab/newline are
15  # collapsed to spaces below anyway). Prevents log-line forging and terminal
16  # escape tricks in anything that echoes the question.
17  _CONTROL_CHARS = re.compile(r"[\x00-\x08\x0b\x0c\x0e-\x1f\x7f-\x9f]")
18  _WHITESPACE = re.compile(r"\s+")
19  
20  # Phrases we record (not block) — blocking on wording is brittle and easy to
21  # evade, so we surface them in the audit trail rather than reject, and let the
22  # structural defenses do the actual protecting.
23  _INJECTION_PATTERNS = [
24      re.compile(r"ignore (all |the )?(previous|prior|above) (instructions|prompts)", re.I),
25      re.compile(r"disregard (all |the )?(previous|prior|above)", re.I),
26      re.compile(r"system prompt", re.I),
27      re.compile(r"you are now", re.I),
28      re.compile(r"drop\s+table", re.I),
29      re.compile(r"delete\s+from", re.I),
30  ]
31  
32  
33  class QuestionRejected(Exception):
34      """Raised when input can't be made into a usable question. `code` is one of
35      'empty' or 'too_long' so the caller can respond politely per case."""
36  
37      def __init__(self, message, code):
38          super().__init__(message)
39          self.code = code
40  
41  
42  def sanitize_question(raw):
43      """Return (clean_text, flags). Raises QuestionRejected for empty or
44      over-length input. `flags` lists any injection-style patterns seen — for
45      the audit log, not for blocking."""
46      text = _CONTROL_CHARS.sub("", str(raw or ""))
47      text = _WHITESPACE.sub(" ", text).strip()
48  
49      if not text:
50          raise QuestionRejected("the question is empty", code="empty")
51      if len(text) > MAX_QUESTION_LENGTH:
52          raise QuestionRejected(
53              f"the question is too long ({len(text)} chars; max {MAX_QUESTION_LENGTH})",
54              code="too_long",
55          )
56  
57      flags = [p.pattern for p in _INJECTION_PATTERNS if p.search(text)]
58      return text, flags

15  # token-level net in case a future parser edge case ever lets one slip
16  # through. Checking *token type* rather than raw text/regex matters: a
17  # course literally titled "Update Systems" tokenizes UPDATE as a plain
18  # STRING, not a TokenType.UPDATE keyword, so it won't false-positive here
19  # the way a naive `\bUPDATE\b` regex over the raw SQL text would.
20  _HARD_FORBIDDEN_TOKEN_TYPES = {
21      TokenType.INSERT,
22      TokenType.UPDATE,
23      TokenType.DELETE,
24      TokenType.DROP,
25      TokenType.ALTER,
26  }

39  def validate_and_cap(raw_model_output, allowed_tables, max_limit=MAX_LIMIT):
40      """Turns raw LLM output into a safe-to-run SQL string, or raises
41      SqlRejected. Never returns anything but a single capped SELECT."""
42      text = _strip_code_fences(raw_model_output).rstrip(";").strip()
43  
44      if not text or text.upper() == "NO_QUERY":
45          raise SqlRejected("the model reported it could not answer this question with the given schema")
46  
47      try:
48          statements = [s for s in sqlglot.parse(text, read=DIALECT) if s is not None]
49      except Exception as exc:
50          raise SqlRejected(f"generated SQL failed to parse: {exc}") from None
51  
52      if len(statements) != 1:
53          raise SqlRejected(
54              f"expected exactly one SQL statement, got {len(statements)} "
55              "(stacked/multiple statements are not allowed)"
56          )
57  
58      stmt = statements[0]
59  
60      if not isinstance(stmt, exp.Select):
61          raise SqlRejected(f"only SELECT statements are allowed, got {type(stmt).__name__}")
62  
63      hit_types = {tok.token_type for tok in Tokenizer().tokenize(text)} & _HARD_FORBIDDEN_TOKEN_TYPES
64      if hit_types:
65          raise SqlRejected(f"query contains forbidden keyword(s): {', '.join(t.name for t in hit_types)}")
66  
67      referenced_tables = {t.name.lower() for t in stmt.find_all(exp.Table) if t.name}
68      allowed_lower = {t.lower() for t in allowed_tables}
69      disallowed = referenced_tables - allowed_lower
70      if disallowed:
71          raise SqlRejected(
72              f"query references table(s) outside the allowed schema: {', '.join(sorted(disallowed))}"
73          )
74  
75      return _cap_limit(stmt, max_limit).sql(dialect=DIALECT)

79      stmt = stmt.copy()
80      stmt.set("offset", None)  # pagination isn't supported by this agent
81  
82      existing_limit_node = stmt.args.get("limit")
83      existing_value = None
84      if existing_limit_node is not None:
85          try:
86              existing_value = int(existing_limit_node.expression.this)
87          except (AttributeError, TypeError, ValueError):
88              existing_value = None
89  
90      final_limit = min(existing_value, max_limit) if existing_value is not None else max_limit
91      return stmt.limit(final_limit)

 4  # db/sql/create_rag_agent_ro.sql / sync_worker/config.py) — the agent can
 5  # only ever see and query general institutional data, never the per-student

 8      "departments",
 9      "faculty",
10      "programs",
11      "courses",
12      "courses_prerequisites",
13      "course_offerings",
14      "rooms",
15      "class_schedule",
16      "exam_timetable",
17      "fee_structure",
18  ]

20  _COLUMNS_SQL = """
21      SELECT table_name, column_name, data_type
22      FROM information_schema.columns
23      WHERE table_schema = 'public' AND table_name = ANY(%s)
24      ORDER BY table_name, ordinal_position;
25  """
26  
27  _FK_SQL = """
28      SELECT
29          tc.table_name AS from_table,
30          kcu.column_name AS from_column,
31          ccu.table_name AS to_table,
32          ccu.column_name AS to_column
33      FROM information_schema.table_constraints tc
34      JOIN information_schema.key_column_usage kcu
35          ON tc.constraint_name = kcu.constraint_name AND tc.table_schema = kcu.table_schema
36      JOIN information_schema.constraint_column_usage ccu
37          ON tc.constraint_name = ccu.constraint_name AND tc.table_schema = ccu.table_schema
38      WHERE tc.constraint_type = 'FOREIGN KEY' AND tc.table_schema = 'public'
39        AND tc.table_name = ANY(%s);
40  """
41  
42  
43  def build_schema_text(conn):
44      """Introspects the live DB (as rag_agent_ro) for the whitelisted tables,
45      so the prompt always reflects what the agent is actually allowed to
46      query — it can never drift from db/sql/create_rag_agent_ro.sql."""
47      with conn.cursor() as cur:
48          cur.execute(_COLUMNS_SQL, (ALLOWED_TABLES,))
49          columns_by_table = {}
50          for table_name, column_name, data_type in cur.fetchall():
51              columns_by_table.setdefault(table_name, []).append((column_name, data_type))
52  
53          cur.execute(_FK_SQL, (ALLOWED_TABLES,))
54          foreign_keys = {}
55          for from_table, from_column, to_table, to_column in cur.fetchall():
56              foreign_keys[(from_table, from_column)] = (to_table, to_column)
57  
58      lines = []
59      for table in ALLOWED_TABLES:
60          if table not in columns_by_table:
61              continue
62          lines.append(f"TABLE {table} (")
63          for column_name, data_type in columns_by_table[table]:
64              fk = foreign_keys.get((table, column_name))
65              suffix = f" REFERENCES {fk[0]}({fk[1]})" if fk else ""
66              lines.append(f"  {column_name} {data_type}{suffix},")
67          lines.append(")")
68          lines.append("")
69  
70      return "\n".join(lines)

31      """Natural language question -> validated+capped SQL -> (optionally) results.
32  
33      Every generated query is logged via the "sql_agent" logger *before* it's
34      ever executed — including ones that get rejected — so there's always an
35      audit trail of what the LLM produced, independent of whether it ran.
36      """
37      # Schema introspection connects to the DB; if it's unreachable, fail fast
38      # with a user-safe DatabaseUnavailable rather than a raw psycopg2 trace.
39      try:
40          conn = psycopg2.connect(connect_timeout=CONNECT_TIMEOUT_S, **db.RAG_AGENT_RO_CONFIG)
41      except psycopg2.OperationalError as exc:
42          raise DatabaseUnavailable(f"could not connect to database: {exc}") from exc
43      try:
44          schema_text = schema.build_schema_text(conn)
45      except psycopg2.OperationalError as exc:
46          raise DatabaseUnavailable(f"database connection lost during schema read: {exc}") from exc
47      finally:
48          try:
49              conn.close()
50          except Exception:
51              pass
52  
53      raw_output = llm_client.generate_sql(question, schema_text)
54  
55      try:

57      except guard.SqlRejected as exc:
58          logger.warning("REJECTED question=%r raw_llm_output=%r reason=%s", question, raw_output, exc)
59          return SqlAgentResult(question, raw_llm_output=raw_output, error=str(exc))
60  
61      logger.info("question=%r generated_sql=%s", question, capped_sql)
62  
63      if not execute:
64          return SqlAgentResult(question, raw_llm_output=raw_output, generated_sql=capped_sql)
65  
66      try:
67          columns, rows = executor.run_query(capped_sql)
68      except DatabaseUnavailable:
69          # Infrastructure failure — let the orchestrator decide how to degrade,
70          # instead of burying a raw error string in the result.
71          raise
72      except Exception as exc:
73          # A query-level error (e.g. Postgres rejects a valid-looking SELECT).
74          # This is data-shaped, not infrastructure — record it and carry on.
75          logger.exception("query execution failed question=%r sql=%s", question, capped_sql)

17  def poll_table(conn, table, last_updated_at, seen_ids_at_last_ts):
18      """Fetch rows changed since the watermark, classify each as new/updated.
19  
20      Watermark is a (last_updated_at, seen_ids_at_last_ts) pair rather than a
21      bare timestamp: polling with `updated_at >= watermark` can re-fetch rows
22      already processed in a prior cycle if several rows share the exact same
23      updated_at as the watermark, so seen_ids_at_last_ts lets us skip those
24      without risking `>` silently dropping same-timestamp rows we haven't
25      seen yet.
26      """
27      query = sql.SQL(
28          "SELECT * FROM {table} WHERE updated_at >= %s ORDER BY updated_at ASC, id ASC;"
29      ).format(table=sql.Identifier(table))
30  
31      with conn.cursor(cursor_factory=psycopg2.extras.RealDictCursor) as cur:
32          cur.execute(query, (last_updated_at,))
33          rows = cur.fetchall()
34  
35      changes = []
36      new_last_updated_at = last_updated_at
37      new_seen_ids = set(seen_ids_at_last_ts)
38  
39      for row in rows:
40          row_id = row["id"]
41          row_updated_at = row["updated_at"]
42  
43          if row_updated_at == last_updated_at and row_id in seen_ids_at_last_ts:
44              continue
45  
46          op = "new" if row["created_at"] == row["updated_at"] else "updated"
47          changes.append(
48              {
49                  "table": table,
50                  "op": op,
51                  "pk": row_id,
52                  "updated_at": row_updated_at.isoformat(),
53                  "row": {k: _json_safe(v) for k, v in row.items()},
54              }
55          )
56  
57          if row_updated_at > new_last_updated_at:
58              new_last_updated_at = row_updated_at
59              new_seen_ids = {row_id}
60          elif row_updated_at == new_last_updated_at:
61              new_seen_ids.add(row_id)
62  
63      return changes, new_last_updated_at, new_seen_ids
